# USER_GUIDE — как пользоваться IIRuchating

Руководство для разработчика, который держит много локальных репозиториев.

---

## 1. Первый запуск

1. Укажите корневые директории в `.env`:

   ```
   SCAN_ROOTS=/home/user/projects,/home/user/work
   ```

2. Запустите приложение (`docker compose up -d`).
3. Откройте <http://127.0.0.1:8000>.
4. Нажмите **«Сканировать»** — приложение найдёт все `.git` в указанных корнях.

---

## 2. Дашборд

На главной — сводка:

- **Всего репозиториев** — сколько найдено.
- **Требуют внимания** — `dirty`, `diverged`, `behind`, `ahead`.
- **Не отслеживаются** — найдены, но не добавлены в список.
- **Ошибки** — репозитории, к которым нет доступа или сломан remote.

Список можно фильтровать:

| Фильтр | Что показывает |
|--------|----------------|
| Все | все найденные |
| Требуют внимания | `dirty`, `diverged`, `behind`, `ahead` |
| Не отслеживаются | `tracked=false` |
| Чистые | `current` |

---

## 3. Состояния репозитория

| Состояние | Что означает | Что делать |
|-----------|--------------|------------|
| `current` | Всё закоммичено и запушено | Ничего |
| `dirty` | Есть незакоммиченные изменения | Закоммитить или stash |
| `ahead` | Есть незапушенные коммиты | `git push` |
| `behind` | Удалённый ушёл вперёд | `git pull` |
| `diverged` | И локальные, и удалённые коммиты | `git pull --rebase` или merge |
| `no_upstream` | Нет tracking-ветки | `git branch --set-upstream-to=origin/main` |
| `detached` | Detached HEAD | Переключиться на ветку |

**Важно:** `dirty` может сочетаться с `behind`/`diverged`. Всегда смотрите на детали.

---

## 4. Неучтённые репозитории

Если сканирование нашло репозиторий, которого нет в списке отслеживаемых, он появляется в секции **«Не отслеживаются»** с пометкой `untracked`. Нажмите **«Отслеживать»**, чтобы добавить его в основной список.

Так вы не пропустите проект, который случайно склонировали и забыли.

---

## 5. Детали репозитория

Клик по карточке открывает:

- **Ветка и upstream** — `main → origin/main`.
- **Ahead/Behind** — насколько вы впереди/позади.
- **Изменённые файлы** — modified / staged / untracked / conflicted.
- **Последние коммиты** — что было сделано.
- **Рекомендации** — готовые команды (только для копирования, не выполняются автоматически).

---

## 6. Обновление статуса

Статус кэшируется на 60 секунд. Кнопка **«Обновить»** на карточке или в деталях заставляет пересчитать статус и выполнить `git fetch`.

---

## 7. Частые вопросы

**Почему `ahead/behind` показывают 0, хотя на GitHub есть новые коммиты?**
Потому что `fetch` не выполнялся (нет сети или истёк токен). Статус помечен как `stale`. Нажмите «Обновить» или проверьте `GITHUB_TOKEN`.

**Приложение не видит репозиторий.**
Проверьте `SCAN_ROOTS` и `SCAN_DEPTH`; репозиторий должен содержать `.git`. Возможно, он исключён через `SCAN_IGNORE`.

**Можно ли запустить `pull` из приложения?**
В v0.1.0 — нет. Приложение только показывает рекомендации. Мутации появятся в v0.2.0 с подтверждением.

**Это безопасно? Не потеряю ли я изменения?**
Да. Все операции чтения не изменяют рабочую директорию. Fetch обновляет только `refs/remotes/*`.
