# ADR-0023: агрегация и кэширование global stats

**Дата:** 2026-11-11 · **Статус:** принято · **Спринт:** S63-001

## Контекст

Дашборд должен показывать технический долг по всем tracked-репозиториям:
outdated-пакеты, CVE, dirty-файлы и diverged-ветки. Если считать это на каждый
HTTP-запрос, дашборд будет ждать сетевые реестры и OSV, а на 30+ репозиториях
легко получить таймауты и шторм одинаковых проверок.

При этом источники данных уже существуют и имеют собственные TTL-кэши:
`DependencyService` (реестры), `SecurityService` (OSV), `repository_status`
(локальный Git). Новых мутаций и походов в Git не требуется.

## Решение

`GlobalStatsService` — read-only агрегатор поверх существующих сервисов.

- Берутся только `repositories.tracked = true`; нет tracked-репозиториев —
  отчёт с нулями и HTTP 200.
- `DependencyService.get_report(ecosystem="all")` и
  `SecurityService.get_report(include_secrets=False, min_severity="all")`
  вызываются с `refresh=false`, то есть используют свои кэши.
- Параллелизм ограничен `asyncio.Semaphore(GLOBAL_STATS_CONCURRENCY)` (по
  умолчанию 4), чтобы не перегружать реестры и диск.
- Результат хранится **только в памяти** процесса: TTL
  `GLOBAL_STATS_CACHE_TTL_SECONDS` (300 с). Новых таблиц и миграций нет.
- `refresh=true` обходит кэш и пересобирает отчёт; параллельные запросы
  сериализуются одним `asyncio.Lock` (single-flight), поэтому первый запрос
  строит отчёт, остальные получают свежую копию.
- `problem_score` — детерминированная формула SPEC §3.34.1; топ-5 считается
  по score desc и имени, записи с нулевым score в топ не попадают.
- Ошибка одного источника даёт `status="partial"`/`error` у репозитория и
  HTTP 200; полностью недоступный scope получает
  `error="all_sources_unavailable"`, а не 500.
- AI-отчёт получает только агрегаты, имена репозиториев и счётчики. Пути, код,
  diff, версии пакетов и описания CVE в промпт не передаются. Кэш — общий
  `ai_cache` с ключом по состоянию агрегатов.

## Последствия

- Первый запрос после старта/истечения TTL стоит столько же, сколько обход
  кэшей источников; последующие — доли миллисекунды.
- Несколько воркеров процесса имеют независимые in-memory кэши; это осознанно:
  отчёт не критичен, а общая БД-таблица усложнила бы миграции и блокировки.
- `stale=true` показывает, что источник отдал значение из просроченного кэша;
  UI помечает такие данные, но не скрывает их.
- Метрики: `global_stats_duration_seconds`,
  `global_stats_cache_hits_total`, `global_stats_partial_total`.
