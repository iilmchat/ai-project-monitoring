# ADR-0005: Политика межпровайдерного зеркалирования (GitHub ↔ GitFlic)

**Статус:** Accepted
**Дата:** 2026-11-05
**Контекст:** R8/R9; миграция большинства проектов с GitHub на GitFlic; часть проектов — приватные.

## Контекст

Проекты могут существовать в трёх состояниях: только GitHub, только GitFlic, оба. Большинство — приватные. План: **сейчас canonical=github, затем переезд на canonical=gitflic**. Без явной политики мониторинг будет либо шуметь («почему этого нет в GitFlic?!»), либо молчать о реальной рассинхронизации.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. GitHub канонический всегда | Просто | Неверно для проектов, которые осознанно только на GitFlic; не поддерживает миграцию |
| B. GitFlic канонический всегда | Просто | Неверно для этапа миграции |
| C. Явное поле `canonical_provider` на репозиторий | Гибко, поддерживает миграцию | Нужно заполнять при добавлении |
| D. «Оба равноправны» (сравнивать, но не алертить на missing) | Меньше шума | Пропускает реальные забытые зеркала |

## Решение

**Вариант C + D как fallback.**

- У каждого репозитория: `canonical_provider` (`github | gitflic | both`), `mirror_expected` (bool), `mirror_policy` (default `github_to_gitflic`).
- **Default:** `canonical_provider=github`, `mirror_expected=true` — этап миграции.
- При `mirror_expected=true` и `canonical=github`: `missing_on_gitflic`, `behind_gitflic`, `diverged`, `history_rewritten` — **алерт** («Требуют внимания»).
- При `mirror_expected=false`: отсутствие/расхождение — **не проблема**, показывается серым.
- При `canonical=both`: сравнивать, при расхождении — warning, не алерт (пользователь сам решает).
- `history_rewritten` — **всегда критический алерт** независимо от политики.

## Последствия

- Дашборд не шумит по осознанно односторонним проектам.
- Реальная рассинхронизация и force-push видны.
- При переезде на GitFlic — переключить `canonical_provider` на уровне репозитория (или пакетно, через UI).
- Нужны `GITHUB_TOKEN` и `GITFLIC_TOKEN` с доступом к приватным проектам — иначе `missing_on_*` будет ложно-положительным; UI должен показывать `unavailable`, а не `missing`.
- Polling (300 с) + webhook — обязательны для своевременного обнаружения.
