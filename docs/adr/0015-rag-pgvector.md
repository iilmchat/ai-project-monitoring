# ADR-0015: RAG-поиск по коду на PostgreSQL + pgvector

**Статус:** Accepted
**Дата:** 2026-11-08
**Контекст:** Спринт 44 (S44-001..S44-004), релиз v0.9.0

## Контекст

Нужен семантический поиск по README, `docs/` и исходникам всех tracked-проектов
(«где у меня настроен Redis?»). Проект по умолчанию работает на SQLite, но
векторный поиск и HNSW-индексы в SQLite отсутствуют. Индексация не должна
изменять репозитории и не должна ронять остальные функции при отсутствии
PostgreSQL или модели эмбеддингов.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| PostgreSQL + `pgvector` | Нативный cosine search, HNSW, привычный SQLAlchemy | Нужен PostgreSQL и расширение |
| SQLite + `sqlite-vss`/`faiss` | Работает локально | Новые бинарные зависимости, слабая поддержка |
| Внешняя векторная БД (Qdrant/Chroma) | Мощный поиск | Ещё один сервис, сложность развёртывания |
| Полнотекстовый `LIKE`/FTS | Просто | Не решает семантический поиск |

## Решение

- Векторное хранилище — PostgreSQL + `pgvector`; миграция `011` создаёт
  `code_chunks` и HNSW-индекс только на PostgreSQL. На SQLite миграция — no-op,
  API возвращает `503 rag_unavailable`.
- Эмбеддинги — OpenAI-compatible `POST /v1/embeddings` через `LLMService.embed`
  (`EMBEDDING_BASE_URL`, `EMBEDDING_MODEL`, `EMBEDDING_DIMENSIONS`,
  `EMBEDDING_ALLOW_REMOTE`). По умолчанию — `text-embedding-3-small`, 1536
  измерений; локальная модель настраивается.
- Чанкинг — окно по строкам `RAG_CHUNK_CHARS` (1000) с перекрытием
  `RAG_CHUNK_OVERLAP` (150), сохраняются `start_line`/`end_line`.
- Инкрементальность — hash содержимого чанка; неизменённый файл пропускается,
  изменённые чанки переэмбеддируются и старые удаляются.
- Ограничения: `RAG_MAX_FILE_BYTES` (512 KiB), `RAG_MAX_CHUNKS_PER_REPO`
  (2000), батчи `EMBEDDING_BATCH_SIZE` (32).
- Read-only: сервис только читает файлы; `.git`, индекс Git и рабочие файлы не
  меняются.
- `asyncpg` добавлен как async-драйвер PostgreSQL. Python-пакет `pgvector` не
  требуется: SQL использует `CAST(:embedding AS vector)` и `<=>`.

## Последствия

- RAG полностью доступен только на PostgreSQL; dev/CI на SQLite проверяет
  деградацию `503 rag_unavailable`.
- При смене модели/размерности нужна миграция `vector(N)` и полная
  переиндексация; сервис возвращает `embedding_dimension_mismatch`.
- Индексация больших монорепозиториев ограничена памятью (KI-017); HNSW
  строится после вставки, лимиты и батчи настраиваются.
- Запросы, фрагменты и эмбеддинги не логируются; `.env`, ключи и lock-файлы не
  индексируются, секреты в сниппетах маскируются.
