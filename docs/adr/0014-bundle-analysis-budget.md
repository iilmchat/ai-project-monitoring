# ADR-0014: Анализ бандла и бюджет entry chunk

**Статус:** Accepted
**Дата:** 2026-11-08
**Контекст:** Спринт 42 (S42-002), v0.9.0 «Search & Reliability»

## Контекст

Entry bundle вырос до 99.0 kB gzip. Основной вклад давали словари i18n, которые
импортировались синхронно в `LanguageProvider`, хотя нужны только на отдельных
маршрутах. Нужен воспроизводимый способ измерять состав бандла и не допускать
регрессий.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| `rollup-plugin-visualizer` | Точные размеры по модулям, treemap, gzip-оценка | Новая dev-зависимость |
| `vite-bundle-visualizer` | Запускается одной командой | Меньше контроля над режимом сборки |
| `vite build --sourcemap` + разбор `dist` | Без зависимостей | Нет наглядной атрибуции модулей |

## Решение

- `rollup-plugin-visualizer` подключён только в режиме `analyze`; отчёт пишется
  в `frontend/dist/stats.html` и не коммитится.
- Скрипт `pnpm build:analyze` собирает production-бандл с отчётом.
- Бюджет проверяется отдельным скриптом `frontend/scripts/check-bundle-budget.mjs`
  (без новых зависимостей): он читает единственный `dist/assets/index-*.js`,
  считает gzip через `node:zlib` и падает при размере ≥ 90 kB.
- Словари `settings`, `repository` и `components` вынесены в ленивые чанки через
  динамический `import()`; базовые `common`/`dashboard` остаются eager.
- Для ES2023-браузеров отключён `modulePreload` polyfill.

## Последствия

- Entry bundle: 99.0 → 89.9 kB gzip (по отчёту Vite); бюджет-скрипт даёт 86.7 kB
  при gzip level 9.
- Появились дополнительные чанки словарей; их загрузка начинается при переходе на
  `Settings`/`RepositoryDetails` и на дашборд (для `components`).
- Новые тяжёлые зависимости или синхронные импорты словарей теперь ловятся
  проверкой `pnpm check:bundle`.
- При переходе на другой сборщик или формат чанков скрипт бюджета потребуется
  обновить.
