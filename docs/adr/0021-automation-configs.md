# ADR-0021: Automation config generation (no push)

**Статус:** Accepted
**Дата:** 2026-11-11
**Контекст:** Спринт 59 (S59-002), v1.3.0

## Контекст

Dependabot/Renovate создают PR на стороне GitHub/GitLab, но для этого им нужен
конфигурационный файл в репозитории. Приложение остаётся read-only по
умолчанию и не должно коммитить или пушить изменения.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Автоматически писать конфиг и коммитить | Удобно | Нарушает read-only, нужен push |
| Писать файл только по confirm + audit | Полуавтомат | Всё равно мутация и риск конфликтов |
| Только генерировать текст и отдавать пользователю | Безопасно, предсказуемо | Ручное копирование |
| Вызывать GitHub API для PR | Полный автомат | Нужны токены/права, вне scope |

## Решение

- `POST /api/v1/repositories/{id}/automation/generate` принимает
  `{tool: "dependabot" | "renovate"}` и **возвращает только текст** конфига
  (`content`), путь, `content_hash`, найденные экосистемы и warnings.
- Экосистемы и каталоги определяются через `ManifestDiscovery`
  (Python/Node/.NET).
- Dependabot: `pip`/`npm`/`nuget`, weekly, limit 5, groups minor/patch.
- Renovate: `config:recommended`, packageRules и `enabledManagers`.
- Файлы не создаются, commit/push не выполняются, `confirm` не требуется.
- UI показывает модалку с предпросмотром и кнопкой «Скопировать».

## Последствия

- Нулевой риск случайной мутации/конфликта и никаких дополнительных прав.
- Пользователь сам копирует конфиг и коммитит; после этого PR создаёт
  GitHub/GitLab.
- Нет автоматической проверки YAML схемой GitHub — только структурная
  генерация и JSON-валидация Renovate.
- Будущий `apply` потребует отдельного ADR, preflight и audit.
