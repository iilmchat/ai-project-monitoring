# ADR-0010: Local-first LLM integration for commit messages

**Статус:** Accepted
**Дата:** 2026-11-06
**Контекст:** Sprint 32 (S32-001…S32-006), SPEC §3.12/§3.18.1, ARCHITECTURE §15

## Контекст

Нужно генерировать черновик commit message по локальным изменениям. Код
репозитория может содержать приватные данные и секреты, поэтому отправлять diff
во внешний SaaS по умолчанию нельзя. Пользователь должен иметь возможность
подключить локальный Ollama или LM Studio, а также явно разрешить remote
endpoint, если осознанно этого хочет.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Облачный LLM по умолчанию | Качество, скорость | Утечка кода, стоимость, зависимость от сети |
| B. Локальный OpenAI-совместимый endpoint + opt-in remote | Приватность, Ollama/LM Studio, без новых зависимостей | Качество зависит от модели, нужен запущенный сервер |
| C. Собственная модель / fine-tune | Полный контроль | Несоразмерно задаче |

## Решение

**Вариант B.**

- `LLMService` общается с `POST {base_url}/v1/chat/completions` через `httpx`
  (уже есть в проекте). Поддержка Ollama/LM Studio — за счёт совместимости API.
- По умолчанию `LLM_ENABLED=false`; приложение не стучится в модель при старте.
- `LLM_BASE_URL` по умолчанию loopback (`http://127.0.0.1:1234/v1`).
  Не-loopback host блокируется, пока не задан `LLM_ALLOW_REMOTE=true`.
- Diff готовит backend: `git diff HEAD --no-color --no-ext-diff --unified=3`,
  лимит `LLM_MAX_DIFF_CHARS` (10000), при обрезке — `[diff truncated]`.
- Промпт требует Conventional Commits и «только текст коммита». Ответ очищается
  от Markdown-обёрток/кавычек; содержательная валидация не выполняется —
  пользователь редактирует текст в модалке.
- Ошибки LLM/timeout/5xx → `503`; fallback-сообщение не подставляется, чтобы не
  создавать ложное впечатление сгенерированного текста.
- Diff, промпты, ответы и `llm_api_key` не логируются и не сохраняются в БД.
- Автоматического `git commit` нет. Отдельное действие `commit` требует
  `confirm=true`, непустое сообщение и пишется в `action_log`.

## Последствия

- Приватность по умолчанию: код не покидает машину.
- Для remote LLM нужен явный opt-in и предупреждение в UI.
- Медленная/недоступная модель не ломает карточку: UI показывает toast.
- Качество и галлюцинации остаются на усмотрение модели (KI-013); пользователь
  обязан проверить сообщение перед коммитом.
- CVE-объяснение (Sprint 33) переиспользует тот же клиент и remote-guard.
