# ADR-0008: Dependency checks without package-manager execution

**Статус:** Accepted
**Дата:** 2026-11-06
**Контекст:** Sprint 25 (S25-001…S25-007), SPEC §3.15, ARCHITECTURE §11

## Контекст

Нужно показывать устаревшие Python-зависимости локальных репозиториев, не
изменяя их и не запуская `pip`. `requirements.txt` может содержать pins,
диапазоны, extras, environment markers, include-файлы и нестандартные ссылки.
Запрос на каждый пакет к PyPI легко упирается в rate-limit при повторном
открытии карточки или перезапуске backend.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. `pip index versions` / `pip install --dry-run` | Точная семантика pip | Запускает пакетный менеджер, медленно, зависит от окружения, может писать кэш/сеть |
| B. Только `pip freeze`/lock-файл | Просто | Не отражает объявленные зависимости; lock-файлы не всегда есть |
| C. Собственный парсер + registry HTTP + TTL-кэш | Read-only, быстро, тестируемо, единый контракт | Не разрешает транзитивные зависимости и сложные диапазоны |
| D. Полный resolver (packaging/semver) | Точные диапазоны | Новая зависимость, сложность, всё равно не нужен для v0.5.0 |

## Решение

**Вариант C.**

- `requirements.txt` читается только внутри корня репозитория; `-r` include
  ограничен глубиной 3, циклами и path traversal; `-c`/constraints не
  раскрываются.
- Для проверки используется PyPI JSON API (`info.version`), а не `pip`.
- Сравнивается release-часть версии (`major.minor.patch`); для `exact` — точная
  версия, для `range` — нижняя граница. Сложные диапазоны дают `unknown`, а не
  ложный `outdated`.
- Кэш `dependency_cache` с TTL 24 ч; ключ `pypi:<normalized-name>`; запись
  переживает перезапуск. Stale-кэш используется при ошибке реестра.
- Ошибки реестра (`rate_limited`, `registry_unavailable`, `timeout`) возвращаются
  как partial report (`status=unavailable`/`stale_cache`), HTTP 200.
- Новые Python-зависимости не добавляются: `httpx` уже используется
  провайдерами, сравнение версий — собственное.

## Последствия

- Проверка не запускает `pip`/`npm` и не меняет рабочую директорию репозитория.
- Транзитивные зависимости и lock-файлы не анализируются — это явно вне scope
  v0.5.0.
- Для Node используется отдельный парсер `package.json` и npm-клиент с той же
  таблицей кэша (реализовано в Sprint 26).
- Приватные registry, аутентификация и CVE-аудит — в следующих версиях.
