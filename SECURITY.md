# SECURITY — политика безопасности IIRuchating

## 1. Модель угроз (v0.1.0)

Приложение работает **локально**, bind на `127.0.0.1`, без аутентификации.
Основные риски:

| Риск | Митигация |
|---|---|
| Случайная потеря незакоммиченных данных | **Read-only по умолчанию**: никаких мутирующих Git-команд |
| Утечка содержимого репозиториев | Нет внешних вызовов, кроме `git fetch` (read-only для рабочей директории) |
| Компрометация токена GitHub | Токен — в `.env`, не в коде; `.env` в `.gitignore` |
| Path traversal при сканировании | `SCAN_ROOTS` — явный whitelist; никаких `../` из запросов |

## 2. Жёсткие правила для кода и агентов

1. **Никаких `git clean`, `git reset --hard`, `git checkout .`** — автоматически.
2. **`git fetch` — только через `RemoteService`** с таймаутом и обработкой ошибок.
3. **Сканирование не выходит за `SCAN_ROOTS`** — даже если в запросе передан другой путь.
4. **Не логировать содержимое файлов** и diff'ы; только метаданные (пути, статусы).
5. **Секреты — только в ENV**, `.env.example` — только placeholder'ы.
