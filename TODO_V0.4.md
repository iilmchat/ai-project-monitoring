## 2. Принципы

1. **Маленькие итерации:** спринт = законченная UX-порция, `main` всегда зелёный.
2. **Read-only по умолчанию:** мутации только через `confirm=true` и `action_log`.
3. **Один факт — один источник:** SPEC — контракты, ARCHITECTURE — устройство, этот файл — план.
4. **Сначала состояние, потом рендер:** фильтры/сортировка/колонки — в store, не в компонентах.
5. **Сохраняемость:** пользовательские настройки (views/columns/selection) переживают перезагрузку.
6. **A11y не «потом»:** клавиатура и семантика входят в DoD каждого спринта.
7. **Никаких секретов в UI:** токены — только маски, Telegram token — в настройках/ENV.

## 5. Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Раздувание entry bundle (recharts, heatmap, palette) | Высокая | Среднее | lazy + code-splitting, бюджет 100 kB gzip |
| Сложность синхронизации saved views (local vs DB) | Средняя | Среднее | версионированная схема, localStorage в v0.4, БД — v0.5 |
| Регрессии клавиатурной навигации | Средняя | Среднее | единый `useHotkeys`, интеграционные тесты |
| A11y-долг | Средняя | Высокое | иконки/aria в DoD каждого спринта |
| Telegram API rate-limit/секреты | Средняя | Среднее | retry/backoff, токен только в Settings/ENV |
| Conflict Manager читает только unmerged-файлы | Низкая | Низкое | документировать ограничение (не заменяет `git status`) |
| Batch-операции на сотнях репозиториев | Средняя | Высокое | concurrency 5, отмена/прогресс в v0.4.1 |
